## D'où ça vient

Le 5 octobre 2026, en faisant le ménage dans les branches d'un projet, un développeur expérimenté découvre `git fetch --prune`. Pas une option obscure : la réponse à une question qu'il s'était posée des dizaines de fois sans la formuler. « Pourquoi je vois encore cette branche qui a été supprimée ? »

Ce n'est pas un cas isolé. On peut être senior et n'avoir jamais eu besoin de comprendre les références distantes, parce que ça n'a jamais bloqué assez longtemps pour qu'on s'arrête dessus. Les ressources existent, elles sont même excellentes, mais elles sont organisées **par commande**, en anglais, pour quelqu'un qui sait déjà quoi chercher. Or on arrive toujours avec **une situation**.

Ce site est né ce jour-là.

## Ce qu'il promet

- **Partir de la situation**, pas de la commande. Le titre d'une page est ce que tu taperais dans un moteur de recherche.
- **Des sorties vraies.** Chaque commande affichée a été exécutée, par un script versionné avec la page, avec la version de Git indiquée. Rien n'est recopié de mémoire.
- **Toujours le pourquoi.** Une commande sans son modèle mental s'oublie en une semaine.
- **Git d'abord, GitHub étiqueté.** Ce qui vaut pour GitLab ou Bitbucket reste réutilisable.
- **Court.** Une page se lit en cinq minutes. Ce qui dépasse devient une autre page.
- **En français d'abord**, pour les développeurs francophones de tous niveaux, et [en anglais](/en/) depuis le 7 octobre 2026. La page française fait référence ; les commandes et leurs sorties sont les mêmes dans les deux langues.
