## What it's for

`git diff` compares two states and shows what changes between the two, line by line. Without arguments, it compares your working folder to the index; with two references, it compares those two. It never lists commits: for that, it's [`git log`](/en/commandes/log/). The full manual: `git help diff`.

## The forms that matter

**`git diff`**, with nothing: what you modified and haven't added yet with `git add`. `--stat` summarises per file.

```console
$ git diff
diff --git a/recherche.js b/recherche.js
index 093f8ac..b7f845c 100644
--- a/recherche.js
+++ b/recherche.js
@@ -1,3 +1,3 @@
 recherche
 filtre
-tri
+tri par date

$ git diff --stat
 recherche.js | 2 +-
 1 file changed, 1 insertion(+), 1 deletion(-)
```

**`git diff --staged`**: what is in the index, ready to be committed. After a `git add`, plain `git diff` shows nothing any more, that's normal: the change switched sides. `--word-diff` shows words rather than lines, useful on text.

```console
$ git add recherche.js

$ git diff

$ git diff --staged
diff --git a/recherche.js b/recherche.js
index 093f8ac..b7f845c 100644
--- a/recherche.js
+++ b/recherche.js
@@ -1,3 +1,3 @@
 recherche
 filtre
-tri
+tri par date

$ git diff --staged --word-diff
diff --git a/recherche.js b/recherche.js
index 093f8ac..b7f845c 100644
--- a/recherche.js
+++ b/recherche.js
@@ -1,3 +1,3 @@
recherche
filtre
tri {+par date+}
```

**`git diff main...feature`**, three dots: what the branch changed since it left `main`, without what `main` received in the meantime. Without dots, the two branches are compared as they are, and what `main` added shows up as deleted by the branch. `--name-status` gives only the files and their state.

```console
$ git diff --stat main feature/tri
 contact.js   | 1 -
 recherche.js | 1 +
 2 files changed, 1 insertion(+), 1 deletion(-)

$ git diff --stat main...feature/tri
 recherche.js | 1 +
 1 file changed, 1 insertion(+)

$ git diff --name-status main...feature/tri
M	recherche.js
```

**`git diff A B -- file`**: one file between two commits, here between the next-to-last and the last.

```console
$ git diff HEAD~1 HEAD -- recherche.js
diff --git a/recherche.js b/recherche.js
index f7aabde..093f8ac 100644
--- a/recherche.js
+++ b/recherche.js
@@ -1,2 +1,3 @@
 recherche
 filtre
+tri
```

## Pitfalls

- **No dots is not three dots.** `git diff main feature/tri` shows `contact.js` deleted although the branch never touched it: `main` added it in the meantime. Before a pull request, it's always three dots, and that's what GitHub shows in "Files changed".
- **`log` and `diff` have inverted dots** for the same intention: two dots with `log`, three with `diff`. [Seeing what changed between my branch and main](/en/situations/quotidien/voir-ce-qui-a-change/) explains why.
- **Empty `git diff` after `git add`**: the changes moved into the index, `--staged` shows them. `--cached` is the same flag under its old name.
- **The whole file shows up as modified** while one line changed: line endings, almost always. [Git sees all my files as modified](/en/situations/fichiers/tous-les-fichiers-modifies/). `-w` ignores whitespace, for the time it takes to read.
- **`git diff` doesn't see new files** until they are added: `git status` lists them as `??`.
