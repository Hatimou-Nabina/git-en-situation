## What it's for

`git pull` chains two commands: [`git fetch`](/en/commandes/fetch/), which fetches, then `git merge` or `git rebase`, which integrates into your branch what its server branch received. When you committed nothing locally, it's a simple fast-forward. When both sides moved, Git asks you to choose how to reconcile, and that's where everything plays out. The full manual: `git help pull`.

## The forms that matter

**`git pull`**, the simple case: nothing locally, the server moved. The branch moves forward in a straight line, "Fast-forward".

```console
$ git pull
From github.com:equipe/projet
   d0a0b32..4bb498d  main       -> origin/main
Updating d0a0b32..4bb498d
Fast-forward
 contact.js | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 contact.js
```

**When both sides moved**, `git pull` without a setting stops and explains the three choices. The `fetch` happened, the integration didn't.

```console
$ git pull
From github.com:equipe/projet
   4bb498d..1ad2b74  main       -> origin/main
hint: You have divergent branches and need to specify how to reconcile them.
hint: You can do so by running one of the following commands sometime before
hint: your next pull:
hint:
hint:   git config pull.rebase false  # merge
hint:   git config pull.rebase true   # rebase
hint:   git config pull.ff only       # fast-forward only
hint:
hint: You can replace "git config" with "git config --global" to set a default
hint: preference for all repositories. You can also pass --rebase, --no-rebase,
hint: or --ff-only on the command line to override the configured default per
hint: invocation.
fatal: Need to specify how to reconcile divergent branches.
```

**`--ff-only`** refuses anything that isn't a fast-forward: you then know there is a divergence, and you choose knowingly. **`--rebase`** replays your commits on top of the server's, and the history stays a straight line.

```console
$ git pull --ff-only
hint: Diverging branches can't be fast-forwarded, you need to either:
hint:
hint: 	git merge --no-ff
hint:
hint: or:
hint:
hint: 	git rebase
hint:
hint: Disable this message with "git config set advice.diverging false"
fatal: Not possible to fast-forward, aborting.

$ git pull --rebase
Rebasing (1/1)Successfully rebased and updated refs/heads/main.

$ git log --oneline -3
1acd006 feat(recherche): ajoute la barre de recherche
1ad2b74 feat(export): ajoute l export CSV
4bb498d feat(contact): ajoute la page contact
```

**`pull.ff only`** once and for all: `git pull` only does the fast-forward any more, and you pass `--rebase` when needed. That's this site's setting.

```console
$ git config --global pull.ff only
```

**Without a tracking branch**, `pull` doesn't know what to pull: a branch created locally has no counterpart on the server yet.

```console
$ git switch -c feature/filtres
Switched to a new branch 'feature/filtres'

$ git pull
There is no tracking information for the current branch.
Please specify which branch you want to merge with.
See git-pull(1) for details.

    git pull <remote> <branch>

If you wish to set tracking information for this branch you can do so with:

    git branch --set-upstream-to=origin/<branch> feature/filtres

```

## Pitfalls

- **`git pull` by reflex on `main`**, with a forgotten local commit and `pull.rebase false`: a merge, and a "Merge branch 'main' of …" commit nobody wants. `--ff-only` prevents it: [My local branch is behind after a merge on GitHub](/en/situations/avec-les-autres/branche-locale-en-retard-apres-fusion/).
- **Merge or rebase?** Rebase for your own branches, merge when the branch is shared: [git pull asks me to choose between merge and rebase](/en/situations/quotidien/git-pull-merge-ou-rebase/).
- **A `pull --rebase` that stops on a conflict** leaves the rebase in progress, in "detached HEAD". `git rebase --abort` brings back the previous state: [A conflict during a merge or a rebase](/en/situations/reparer/resoudre-un-conflit/).
- **`pull` pulls the tracked branch, not "the server".** On `feature/x`, it's `origin/feature/x` that arrives, not `main`. To integrate `main` into your branch: [Updating my branch with main](/en/situations/avec-les-autres/mettre-ma-branche-a-jour-avec-main/).
- **With changes in progress**, `pull` may refuse, "Your local changes would be overwritten": commit or `stash` first.
