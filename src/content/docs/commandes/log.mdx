## À quoi ça sert

`git log` répond aux questions qui commencent par « quand », « qui » et « quoi » : ce qui a été fait, par qui, dans quel ordre, et surtout ce qu'une branche contient que l'autre n'a pas. C'est la commande la plus exécutée de ce site, presque toujours avec `--oneline`. Le manuel complet : `git help log`.

## Les formes qui servent

**`git log --oneline`** : une ligne par commit, l'identifiant court et le sujet. `-3` limite aux trois derniers.

```console
$ git log --oneline -3
b483d37 test(recherche): couvre la recherche vide
cf6c692 feat(recherche): ajoute la barre de recherche
343f26a fix(app): corrige le demarrage
```

**`git log A..B`** : les commits que `B` a et que `A` n'a pas. La forme la plus utile du site : ce que ma branche apporte, ce que je n'ai pas encore poussé (`origin/main..main`), ce que le serveur a reçu (`main..origin/main`). Trois points et `--left-right` montrent les deux côtés d'un coup, `<` pour le gauche, `>` pour le droit.

```console
$ git log --oneline main..feature/recherche
b483d37 test(recherche): couvre la recherche vide
cf6c692 feat(recherche): ajoute la barre de recherche

$ git log --oneline feature/recherche..origin/main
0699995 feat(contact): ajoute la page contact

$ git log --oneline --left-right origin/main...feature/recherche
< 0699995 feat(contact): ajoute la page contact
> b483d37 test(recherche): couvre la recherche vide
> cf6c692 feat(recherche): ajoute la barre de recherche
```

**`--grep`, `-S`, `-- fichier`** : filtrer par message, par chaîne ajoutée ou retirée dans le contenu, par fichier. `--all` étend la recherche à toutes les branches, pas seulement à celle où l'on est.

```console
$ git log --oneline --all --grep='^fix'
343f26a fix(app): corrige le demarrage

$ git log --oneline --all -S'rechercher'
cf6c692 feat(recherche): ajoute la barre de recherche

$ git log --oneline -- app.js
343f26a fix(app): corrige le demarrage
1e0dab4 feat(app): premiere version
```

**`--format`** compose la ligne qu'on veut, et **`-p`** ajoute à chaque commit son diff.

```console
$ git log -1 --format='%h %an %ad %s' --date=short
b483d37 Awa 2026-10-05 test(recherche): couvre la recherche vide

$ git log -1 -p
commit b483d37b4477140df2cb8b823cc1772273d19782
Author: Awa <awa@example.com>
Date:   Mon Oct 5 10:00:00 2026 +0000

    test(recherche): couvre la recherche vide

diff --git a/recherche.js b/recherche.js
index b94dad6..4f852e2 100644
--- a/recherche.js
+++ b/recherche.js
@@ -1 +1,2 @@
 function rechercher() {}
+// cas de la recherche vide
```

**`--graph --decorate --all`** : les branches, où elles se séparent, et où pointent `HEAD`, les branches et leurs copies du serveur.

```console
$ git log --oneline --graph --decorate --all
* b483d37 (HEAD -> feature/recherche) test(recherche): couvre la recherche vide
* cf6c692 feat(recherche): ajoute la barre de recherche
| * 0699995 (origin/main, origin/HEAD) feat(contact): ajoute la page contact
|/
* 343f26a (main) fix(app): corrige le demarrage
* 1e0dab4 feat(app): premiere version
* d0a0b32 Premier commit
```

## Pièges

- **`log A..B` et `diff A...B`** n'ont pas la même ponctuation pour la même intention. [Voir ce qui a changé entre ma branche et main](/situations/quotidien/voir-ce-qui-a-change/) explique pourquoi, et [`git diff`](/commandes/diff/) montre l'autre côté.
- **`git log` ne montre que ce qui descend de `HEAD`.** Un commit d'une branche supprimée n'y est plus. `--all` élargit aux branches qui existent encore ; le reflog garde le reste : [Retrouver un commit perdu](/situations/reparer/retrouver-un-commit-perdu/).
- **`git log origin/main` lit la copie locale** du serveur, pas le serveur : sans `git fetch` avant, elle date du dernier `fetch`.
- **Un fichier renommé** perd son passé avec `-- fichier` : `--follow` le suit à travers les renommages.
- **`-S` cherche un changement du nombre d'occurrences** de la chaîne, pas une ligne qui la contient : un commit qui déplace la chaîne sans la créer ni la supprimer n'apparaît pas. `-G` prend une expression régulière et trouve aussi les déplacements.
